# Description

"Kape like extract from kape configuration on cold disk". 

[Dissect](https://github.com/fox-it/dissect) wrapper to create Kape like acquisition from a raw disk (or other) and Kape target files (E.g [KapeFiles](https://github.com/EricZimmerman/KapeFiles)).

This project is used in Digital Forensics/Incident Response to create lightweight triage archive containing artefact specified in Kape Targets from the different inputs format supported by dissect : 
  * mounted disk
  * raw
  * vmdk / vmx
  * vbox
  * QCow2
  * e01
  * and more
Use `-l` / `--list` to list available loaders. Some may require extra dependencies.

It's probably not the main tool used for day to day incident response, but useful when previous tools failed to collect artefacts, or when dealing with cold disk. This allows to reuse Kape Targets files (see limitation for minor differences)

* Extract format is (inside a zip archive or as is)
    ```
    target
    ├── .ocd_colt
    ├── YYYY-mm-DDTHH_MM_SS_FFFFFF0_ConsoleLog.txt
    ├── YYYY-mm-DDTHH_MM_SS_FFFFFF0_SkipLog.csv
    ├── YYYY-mm-DDTHH_MM_SS_FFFFFF0_ConsoleLog.txt
    ├── YYYY-mm-DDTHH_MM_SS_FFFFFF0_SkipLog.csv
    ├── LongFileNames [DIR/optional]
    ├── C [DIR]
    └── D [DIR]
    ```
Some information regarding collection :
* If drive letter could not be identified using registries, assign a random drive letter
* Kape targets are processed on all drives

## Usage

```
ocd_colt -vvv -c ~/Documents/tools/kape_configuration/ -t "FileSystem" -K key --in /path/to/toto.E01
# IF multiple disk for the same machine, separate with a +
ocd_colt -v -c ~/Documents/tools/kape_configuration/ -t "\$MFT,\$j"  --in /home/user/VirtualBox\ VMs/Sanbox\ internet/Sanbox\ internet.vdi+/home/user/VirtualBox\ VMs/Sanbox\ internet/Sanbox\ internet_1.vdi
```

## Limitation

* Create `.ocd_colt` in zip root with original file in it (to indicate that archive was generated by this script)
* Does not support wildcard/regex in `FileMask` for alternate data stream 
* Microseconds are not exact, as Kape use 7 digits microseconds representation, and python support only 6. to keep consistent, python microseconds are appended with a 0 ("%Y-%m-%d %H:%M:%S.%f0")

### Differences in behaviour with kape.exe

* Poor performance on Recursive target on whole disk (E.g ):
```yaml
Description: Rclone config file
Author: Eric Capuano
Version: 1.0
Id: 639f9e55-1ee1-4af4-be7c-e6303ffb4b0c
RecreateDirectories: true
Targets:
    -
        Name: Rclone Config
        Category: Apps
        Path: C:\
        FileMask: 'rclone.conf'
        Recursive: true
```
* Apply `MaxSize`/`MinSize` even when collecting file recursively with a wildcard mask.
* Use python regex engine


### Advanced usage

### Encrypted drives

Also support bitlocker decryption using -K flag to provide a Keychain file (see https://docs.dissect.tools/en/latest/usage/disk-encryption.html#keychains for documentation on this format)

```csv
bitlocker,passphrase,b6ad258a-2725-4a42-93c6-844478bf7a90,Password1234
,passphrase,,AnotherTestPassword
```

### Specify loader in Path

File path can include a "scheme" to specify the loader (same as in dissect tools).

E.g :
```bash
# vmx
ocd_colt -c kape_configuration --in "vmx:///path/to/vmware/vm/vm.vmx"
```

### Consider multiple input file as same file system

You can target two file in the same time, so they are considered as the same 'target' and belongs to the same collect (same as in dissect tools).

```
ocd_colt -c kape_configuration --in /path/to/sandbox/sandbox.vdi+/path/to/sandbox/sandbox_1.vdi
```
